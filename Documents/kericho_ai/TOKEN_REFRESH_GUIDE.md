## Why This Happened
WhatsApp temporary access tokens in development expire after 24 hours. Your token expires on **20-May-26 17:00 PDT**, but the current time is **21-May-26 04:45 PDT** (expired).

## Fix: Refresh Your Access Token (2 minutes)

### Option A: Get a Temporary Token (Easiest for Testing)
1. Open https://developers.facebook.com/apps/
2. Log in with your account
3. Select your WhatsApp Business App
4. Go to **WhatsApp > API Setup** (or Setup > Tokens)
5. Find the "Temporary Access Token" section
6. Click **"Generate Token"** or **"Get Access Token"**
7. Copy the new token (starts with `EAAc`)
8. Replace the token in `.env`:

```bash
# Edit /home/lod/Documents/kericho_ai/.env
WHATSAPP_TOKEN=<PASTE_NEW_TOKEN_HERE>
META_ACCESS_TOKEN=<PASTE_NEW_TOKEN_HERE>  # Use the same token
```

9. Save the file
10. Restart the server: Press `Ctrl+C` and run `node src/index.js` again
11. Send a WhatsApp message to your bot number
12. ✅ You should receive an AI-generated reply

### Option B: Get a Permanent System Access Token (For Production)
1. Go to https://developers.facebook.com/apps/{YOUR_APP_ID}/roles/
2. Navigate to **Roles > Roles**
3. Find your user and check if you have **Admin** access
4. If not, ask your app owner to grant you admin access
5. Go to **Settings > Basic**
6. Find and copy your **App Access Token** (this doesn't expire)
7. Replace in `.env`:
```bash
WHATSAPP_TOKEN=<YOUR_APP_ACCESS_TOKEN>
META_ACCESS_TOKEN=<YOUR_APP_ACCESS_TOKEN>
```

## Troubleshooting

### "Still not receiving replies after token refresh?"
1. Check WhatsApp dashboard that this phone number is in **Test Contacts** (if in dev mode) or **Active Contacts** (if in production)
2. Check ngrok URL is correct in the Meta webhook settings (Dashboard > Webhooks)
3. Check Gemini API key is valid: `echo $GEMINI_API_KEY`
4. Check database is connected: `npm run prisma:migrate status`

### "Token keeps expiring?"
Use a **System Access Token** instead (Option B above) - it doesn't expire.

### "Webhook verification failing?"
1. Ensure `WHATSAPP_VERIFY_TOKEN` matches what's in the Meta dashboard
2. Test manually: 
```bash
curl "http://localhost:3000/webhook?hub.mode=subscribe&hub.verify_token=healthcare_ai_verify_token&hub.challenge=test123"
# Should return: test123
```
